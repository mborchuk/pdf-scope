## Requirements

| | |
| --- | --- |
| Python | 3.10 or newer (developed on 3.14, CI covers 3.10–3.14) |
| OS | macOS, Linux, Windows — anywhere PyMuPDF has wheels |
| Disk | Room for a copy of each PDF you open plus its extracted images |
| Network | None needed at runtime; only to install the dependencies |
| Browser | Any current Firefox, Chrome, Edge or Safari |

No system packages, no compiler: PyMuPDF ships binary wheels that bundle MuPDF.

## Install

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt
```

For development, install the test and lint tools as well:

```bash
.venv/bin/pip install -r requirements-dev.txt
```

Everything is pinned to exact versions, PyMuPDF included, so two checkouts of
the same commit behave identically.

## Run

```bash
.venv/bin/python -m pdf_decompiler
```

Open <http://127.0.0.1:8000>.

Command-line options:

| Option | Default | Meaning |
| --- | --- | --- |
| `--host` | `127.0.0.1` | Interface to bind. Read [SECURITY.md](../SECURITY.md) before changing it |
| `--port` | `8000` | Port to listen on |
| `--reload` | off | Restart on source changes; for development only |

The server prints a normal uvicorn banner. Interactive API documentation
generated by FastAPI is at <http://127.0.0.1:8000/docs>.

## Your first document

1. Click **Open PDFs** in the top bar and pick one or several files. They
   upload in one request and are analysed in parallel.
2. Each file appears in the left sidebar with its size, page count and a status
   chip: `queued` → `reading document structure` → `ready`.
3. Click a document to select it. The header shows the PDF version, page count,
   file size, number of xref slots, encryption state, the SHA-256 of the bytes
   and the first eight characters of its document id.
4. If a document is encrypted, its chip reads **waiting for password** and an
   **Unlock** button appears. Enter the user password to continue.
5. A file that cannot be parsed is marked **failed** with the reason. Other
   documents keep working.

## Five-minute tour

| Tab | Try this |
| --- | --- |
| **Page** | Toggle *Spans* and *Drawings* in the toolbar, then click a highlighted box. The right panel shows its text, font, size, colour, bbox and the underlying xref where there is one |
| **Structure** | Expand the page tree, then click any node to jump into the object browser at that xref |
| **Objects** | Type an xref number and press **Load**. Follow a reference such as `12 0 R` with one click |
| **Content stream** | Read the decompiled operator listing: `BT`, `Tf`, `TJ`, `re`, `Do`, each with its operands and a plain-English description |
| **Text** | Copy a single span, a block, the page, or download the whole document as `.txt`/`.md` |
| **Images** | Thumbnails with dimensions, DPI, colourspace, filters and SMask; download one, download all as a zip |
| **Not extractable** | What exists in PDFs but cannot be reached through PyMuPDF, so you know where the edges are |

Then press **Download everything** in the document header: a zip with
`document.json`, one JSON per page, page and document text, every content
stream and every extracted image. **Download everything (all documents)** in
the top bar does the same for every open document at once, one folder each.

## Using it without the UI

The extraction core is a normal Python package with no web dependency:

```python
from pdf_decompiler.core import analyze_document, analyze_page, dumps

report = analyze_document("invoice.pdf")
print(report["file"]["pdf_version"], report["file"]["page_count"])

page = analyze_page("invoice.pdf", 0)
for block in page["text"]["structure"]["blocks"]:
    if block["type"] == "text":
        print(block["bbox"], block["lines"][0]["spans"][0]["text"])

open("page1.json", "w").write(dumps(page))
```

The HTTP API works the same from a shell:

```bash
curl -s -F "files=@invoice.pdf" http://127.0.0.1:8000/api/documents
```

See [core-api.md](core-api.md) and [api.md](api.md).

## Stopping and cleaning up

Press `Ctrl+C` in the terminal. On shutdown the server closes every document
and deletes the workspace directory; the next start begins from an empty
workspace. Nothing is uploaded anywhere at any point.

To remove artifacts by hand:

```bash
rm -rf .workspace
```
